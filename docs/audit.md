# Аудит и план усиления

## Что было найдено

Проект уже имел рабочую основу: старт, каталог, базовый квиз, консультация по смысловой базе книг, оплату в режимах `test/manual/telegram`, выдачу PDF, рассылки по согласию, админ-команды для цен, заказов, текстов и пользователей.

Слабые места до масштабирования:

- диагностика была слишком короткой и не сохраняла полноценный профиль пользователя;
- прогрев был общим для всех сегментов;
- не было событийной аналитики воронки;
- дополнительные услуги были не оформлены как продукты внутри бота;
- не было отдельного сценария для чеков ручной оплаты;
- не было внутриботового мини-курса, лид-магнита и персонального плана после покупки;
- UX не имел единого возврата в главное меню из большинства веток.

## Что усилено

- Добавлена расширенная диагностика из 5 вопросов.
- Добавлены сегменты: `quiet_roots`, `meaning_system`, `burnout_mirror`, `dark_atmosphere`, `complete_world`.
- Добавлена оценка готовности к покупке.
- Добавлены сегментные прогревы вместо одной общей цепочки.
- Добавлена событийная аналитика: старт, согласие, диагностика, выбор продукта, клик покупки, чек, покупка, вопросы, прогревы.
- Добавлены внутриботовые продукты и услуги.
- Добавлен сценарий ручной оплаты через ЮMoney/карту с подтверждением админа.
- Добавлены чек/документ-сценарии: пользователь отправляет чек в бот, бот уведомляет админов.
- Добавлен `/plan` для персонального плана после покупки.
- Добавлен `/deep` для платного ИИ-разбора ситуации.

## Внутриботовые услуги

- Бесплатный лид-магнит `Как выбрать книгу по состоянию`: открывает ценность без внешних площадок.
- Персональная диагностика: главный вход в сегментацию и рекомендацию.
- Мини-курс `Тихая вода внутри`: цепочка уроков и практик внутри бота.
- Платный ИИ-разбор ситуации: покупка, затем команда `/deep`.
- Пакеты `книга + персональный разбор`: книга выдается PDF, разбор остается внутри бота.
- `Комплект + бонусы`: две книги, мини-курс и персональный план чтения внутри бота.

## Ограничения

Настоящая API-интеграция ЮMoney не реализована, потому что для нее нужны дополнительные параметры магазина/кошелька и выбранный юридический сценарий. Сейчас реализован полноценный внутриботовый ручной сценарий: заказ, карта, чек, уведомление админов, подтверждение и выдача.
